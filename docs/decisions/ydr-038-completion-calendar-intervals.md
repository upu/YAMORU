# YDR-038: 完了日基準Todoの月・年単位を対象月の月末へ補正する

- 状態: Accepted
- 決定日: 2026-09-01

## 背景

完了日基準Todoは、実際の完了日から推奨期間の開始と上限を日数で加算している。実利用では「1〜2か月後」「1年後」も必要だが、月を30日、年を365日へ換算すると月末とうるう年で利用者の期待する暦日からずれる。

[YDR-021](ydr-021-recurring-calendar-rules.md)は定例日基準Todoの存在しない月日を対象月の月末へ補正する。この決定は同じ家庭暦と補正原則を、完了日を起点に月・年を加える[Issue #48](https://github.com/upu/YAMORU/issues/48)へ拡張する。固定間隔Todo([YDR-037](ydr-037-fixed-interval-recurrence.md))の候補列は変更しない。

## 決定

### 1. 単位と入力

- 完了日基準Todoの推奨期間は、開始値、上限値、共通の単位を持つ。
- 単位は`day`、`week`、`month`、`year`の4種類とし、一つの推奨期間内で単位を混在させない。
- 開始値は0以上、上限値は開始値以上とする。約10年の既存上限に合わせ、上限値は日3650、週520、月120、年10までとする。
- Todo登録画面は数値入力と単位選択を提供する。月・年を固定間隔Todoへ追加せず、「完了した日から繰り返す」の入力だけを拡張する。

### 2. 暦加算

- 家庭暦とタイムゾーンはYDR-021と同じくAsia/Tokyo固定とする。端末やUTCの日付境界ではなく、実際の完了日時`occurred_at`の東京暦日を起点にする。
- 日は東京暦日をN日、週は7×N日加算する。既存の日・週の結果を変更しない。
- 月は、起点の年月へNか月を一度に加え、起点の日が対象月に存在しなければ対象月の月末へ補正する。月を30日へ換算せず、途中月を反復して加算しない。したがって1月31日の1か月後は2月末、2か月後は3月31日になる。
- 年は、起点の年へN年を一度に加え、起点の月日が対象年に存在しなければ対象月の月末へ補正する。2月29日の1年後は2月28日、4年後は2月29日になる。
- 開始日と上限日は、同じ起点へそれぞれの値を独立に加算する。開始日の計算結果へ差分を加算しない。

### 3. 初回と完了後で同じ計算を使う

- 「前回実施日から計算する」では、入力した前回実施日を起点に開始値と上限値を加える。
- 「次回の目安開始日を指定する」では、入力日を開始日とし、上限日は開始値と上限値の差を同じ単位で入力日へ加える。
- 完了後の次回Occurrenceは、`occurred_at`を起点に同じ暦加算関数で開始日`scheduled_for`と上限日`due_at`を作る。
- `recorded_at`、現在の`scheduled_for`、延期後の`due_at`は次回の起点にしない。完了日基準が実施日時へ吸着する既存の意味を維持する。

### 4. 保存形式と既存データ

- `task_rules`は、利用者が入力した開始値、上限値、単位を失わない列を追加で持つ。月・年を日数へ固定換算して保存しない。
- 既存の日数列は適用済みスキーマおよび移行中の旧Workerとの互換性のため残す。新しい暦加算は値・単位の列を優先し、追加列を持たない既存行は従来の日数列へフォールバックする。
- 日・週の新規登録では、旧日数列にも従来と同じ日数を保存する。月・年の正本は値・単位の列であり、旧日数列を計算に使わない。
- 完了日基準以外のTaskRuleは値・単位の列を持たない。開始値・上限値・単位が部分的に欠けた行は不正として扱う。

### 5. 表示

- Todo詳細は保存した単位を使い、「完了から1〜2か月後」「完了から1年後」のように表示する。
- 追加列を持たない既存行は従来どおり、両方の日数が7で割り切れる場合は週、それ以外は日で表示する。

## 結果

- 初回登録と完了後の次回生成が同じ暦規則になり、月末、うるう日、年またぎでも決定的な結果を返す。
- 日・週の既存挙動と既存行の表示を維持しながら、月・年の入力意図を保存できる。
- 固定間隔Todoの候補列、定例日基準Todo、通知、定例日の複数候補は変更しない。

## 見直す条件

- 家庭ごとのタイムゾーンを追加する場合。
- 「月末を選んだ」という意図を、単なる月末補正と区別して保持する必要が生じた場合。
- 月・年を固定間隔Todoへ追加する場合。
- 営業日・祝日補正や複数単位の混在を追加する場合。
