# YDR-070: v0.21.0は無料運用を維持し、実証した定期取得で通知する

## 背景と変更の根拠

previewの実dotからEventsを購読したところ、検査済みIPへのTCP接続が`tcp_address_disallowed`で、TLS開始前・HTTP未送信のまま拒否された。[#442の実測記録](https://github.com/upu/YAMORU/issues/442#issuecomment-6248032649)に、配備版・処理段階・停止状態を残した。callback URL・IP・鍵は公開しない。公開fixtureやNodeの成功を実callbackの到達と同一視しない。

Cloudflare Containersによる別の送信経路には、現アカウントではWorkers Paidが必要だった。2026-10-18に本人が「無料運用を維持し、定期取得を優先する」と選んだため、v0.21.0の採用経路を変更する。障害を成功扱いにする変更ではなく、本人が選んだ費用・提供範囲の変更である。追加課金、契約変更、Containersの配備は行わない。

ここでの無料運用は、YAMORU側に新しい有料実行基盤を導入しないことを指す。接続先の定期タスクは既存の利用環境の能力・利用条件に従い、すべての接続先やプランで利用できるとは保証しない。

## 置き換える範囲

- [YDR-050](ydr-050-conversation-reminders.md)決定5の「MCP Eventsを第一候補とする」優先順位を、v0.21.0では定期取得を先行する方針へ置き換える。本人設定、家庭共有の予定との分離、候補の正本、返答、停止、既読との区別は維持する。
- [YDR-067](ydr-067-periodic-notification-claims.md)末尾の#442完了条件から、Eventsの実TLS・到達・購読解除・購読失効を切り離す。claim/ack、接続・家庭・本人・leaseの束縛、全件の原子性、unknownの回復・再送防止は置き換えない。
- [YDR-069](ydr-069-pinned-http-runtime.md)の実Events検証を#442の必須条件とした部分だけを、後続[#474](https://github.com/upu/YAMORU/issues/474)へ移す。送信providerの初期無効、固定IP・元hostnameのTLS検証、宛先制限・上限・中断判定は維持する。

既存Events実装と適用済みD1 migrationは保持する。通常fetchや証明書検証の無効化で到達制約を迂回しない。#474はv0.21.0のmilestone・親#189の必須子Issue・#443/#444の前提に加えない。後続採用時は通信経路と費用を改めて決める。

## v0.21.0の通知経路と合格条件

本人が接続先の定期タスクを設定する。YAMORUの永続scheduler/outboxと通知設定は配信可否の正本であり、外部タスクの保存・起動・稼働状態は接続先が管理する。YAMORUの設定を保存するだけで外部タスクが作られたとは表示しない。Eventsの`events.subscribe`権限名は既存のまま、定期取得のclaim/ackにも必要な受信権限として説明する。

1. 初期候補は15分間隔。実行主体、保存済み周期、次回予定、実際の起動・案内報告・dot上の案内、予定からの遅延を分けて記録する。15分ぴったりの起動や到達上限を保証しない。
2. 外部実行は`attention_get`を照合完了まで読み、現在のrevisionで`notification.claim`をprepare/commitする。確保した元Occurrenceを案内直前にも読み、案内後に同じ集合・leaseで`notification.ack`を報告する。候補の取得だけでは案内済みにしない。
3. 完了・通知休止・静かな時間・本人の設定・接続の解除/期限切れを優先する。次の回へ暗黙に対象を付け替えず、他の家族や他の接続の候補を確保しない。定期タスク停止による自動起動の終了と、YAMORUの通知停止による新規確保の拒否は別々に確認する。タスク停止だけでは本人のOAuth接続を解除しない。
4. 再実行、競合、lease切れ、処理中断、保存結果の再取得、障害後の回収を検証する。送信結果不明はunknownとし、無条件再送しない。reportedは案内の報告であり、既読・Todo完了ではない。
5. #442では定期取得による実案内・周期/遅延・重複抑止・停止と、既存の家庭境界・競合・回復テストを照合する。#443は実際の通知への返答、#444は接続から復旧/解除までの実接続と最終回帰、親#189はその全件の完了を確認する。自動実行が用意できない接続は通知未達のままとし、都度照会だけを通知完成と扱わない。

会話連携設計のE3（実Events購読と到達）とE6のEvents購読更新・解除・失効だけを#474へ移す。E6の接続失効・解除後の操作拒否、E7の定期取得、E8の通知返答、および他の家庭境界・同時操作・バックデート等の要件はv0.21.0に残す。

## 配備と確認

この決定は文書と採用範囲の変更であり、DB・scope・既存command・通知設定の初期値を変更しない。preview/productionのEvents providerは未設定を維持する。架空データの一時検証ではタスクを有限回に制限し、終了後にタスクと本人通知を停止し、検証Todoを片付ける。本番への配備・リリース公開は別の作業として扱う。

## 見直す条件

定期取得の遅延・運用負担が日常利用を妨げる、無料環境での安全な送信経路を実証できる、または本人が追加費用を許容する場合に#474で見直す。
