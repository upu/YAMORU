# YDR-059: 通知outboxと走査の進捗をD1に永続化する

[#442](https://github.com/upu/YAMORU/issues/442)で[YDR-050](ydr-050-conversation-reminders.md)・[YDR-056](ydr-056-personal-notification-policy.md)を具体化する。共有予定・個人設定・受領と既読の区別は置き換えない。

## 配信と回復

本人・家庭・接続・候補区間ごとのoutboxを作り、配信IDを再試行でも維持する。有効な試行、不明結果、停止した失敗には一意制約を置く。候補の解消で送信証拠を削除せず、受領・不明の最小記録と詳細履歴は既存の保存方針に従う。新しいIDによる再試行上限の回避を許さない。

送信leaseは5分とし、世代token・状態・DB時刻で各遷移を検証する。送信前のlease切れは同じ配信IDをpendingへ戻す。送信開始後の期限切れは履歴・重複抑止と同じbatchでunknownにし、自動再送しない。古い世代は新しい確保や結果を上書きできない。

開始直前に、家庭revision・本人設定・候補休止・候補revision・所属・接続元・grant・session versionをbatch内で照合する。家族の完了・延期・通知停止を古い判定で通さない。静かな時間やスヌーズは同じ配信の次回時刻を再計算し、回数を消費しない。確保済みでも外へ送る前に再判定する。既に送った結果は解除と競合しても記録する。

既知の一時失敗は30秒から最大1時間の指数backoffに最大25%のjitterを加える。8回・初回送信から24時間を上限とし、送信前にも打ち切りを検査する。応答不明を既知の失敗へ置き換えない。実送信経路の採用には購読・署名・接続時の宛先検証と実到達の証拠を別途要する。

## 定期走査

5分のCronから共通処理をawaitする。接続ごとの走査leaseは2分で期限切れにし、source・候補・未送信outboxの位置を保存する。既定は一回2接続・各25候補とし、処理量を制限して続きは次回へ回す。家庭revisionや暦日が変わればsourceの走査位置を更新し、候補IDの走査は別の位置で継続する。大量の滞留では5分より長くかかるため、これは到達時間の保証ではない。

履歴の削除も一回100件に制限する。ログには処理数と静的な失敗分類を残し、家庭名・候補名・callback・秘密を載せない。Cron入口のローカル成功を、配備済みCronの実行や実dotへの到達として報告しない。

## データと配備

0040はoutboxと走査進捗の追加だけであり、既存ID・時刻・業務履歴を変更しない。接続・本人・家庭の複合FKを使う。親の物理削除では両表をcascadeで削除する。候補の削除ではoutboxを消さず、最新状態の再評価で未送信を終了する。

| 状態 | 互換性 |
|---|---|
| 旧Worker・旧schema | 既存のWeb・共通操作を継続 |
| 旧Worker・0040 | 追加表を使わず、既存のSQL・行・日時を保持 |
| 新Worker・0040 | 永続走査・outboxを利用。旧Workerへ戻しても証拠と進捗は保持 |
| contract後 | 旧構造を置換しないためcontractは不要 |

通常のCI経由でschemaをWorkerより先に適用する。適用済みmigrationは編集せず、問題は追加migrationで修正する。実dotの確認と通知の完成条件が揃うまで#442を閉じない。
