# YDR-043: 横断検索の結果から既存の在庫変更とTodo完了を行えるようにする

- 状態: Accepted
- 決定日: 2026-09-08
- 置き換える決定: [YDR-042](ydr-042-cross-cutting-search.md)(検索結果の続きの操作を詳細画面への移動だけとした部分。検索対象、入口、一致規則、件数上限、家庭単位の認可は変更しない)

## 背景

[YDR-042](ydr-042-cross-cutting-search.md)は、画面を先に選ばず名前から対象へ到達する横断検索を追加し、初期の検索結果は詳細画面へ移動するだけとした。これにより対象は短く見つけられるようになったが、在庫状態の変更やTodo完了のような日常的な操作にも詳細画面を1枚挟む。

[Issue #345](https://github.com/upu/YAMORU/issues/345)で、ホームにピン留めした消耗品から既存の3状態を直接変更する操作を導入した。Issue #375で概念の意味は変えず、名称だけを旧称から変更した。検索結果でも同じ部品を使えば、対象を見つけた場所で短い操作を終えられる。Todoも、ホーム・Todo一覧・管理対象詳細で使っている完了記録ダイアログがすでにあり、検索専用の完了方式を増やさずに再利用できる。

一方、横断検索を汎用編集画面にすると、対象へ到達するという役割が曖昧になり、狭い画面へ操作が増え続ける。追加する操作の基準と境界を先に固定する。

## 検討した案

- **案1(採用)**: 既存画面でもクイック操作として提供している在庫変更とTodo完了だけを、既存部品の再利用で検索結果へ置く。
- 案2: YDR-042のまま詳細画面への移動だけを維持する。構造は単純だが、対象を見つけた後の日常操作を短縮できない。
- 案3: 担当変更、編集、削除も含む共通の操作メニューを置く。検索結果が多機能な編集画面になり、誤操作と表示密度の問題を持ち込むため採用しない。

## 決定

- 横断検索の結果に追加する操作は、次の2つだけとする。
  - 消耗品: 現在状態を示す「ある / 少ない / ない」の3ボタンから、家庭共有の在庫状態を直接変更する。
  - 未完了Todo: 「やったよ」から既存の完了記録ダイアログを開き、現在日時・自分、または実施日・実施した家庭メンバーを指定して記録する。
- 在庫変更は選んだ時点で保存する。別の状態を選び直せる可逆な操作とし、検索専用の確認ダイアログは増やさない。
- Todo完了はボタンだけで即時確定せず、既存ダイアログで記録方法を選んだ後に保存する。完了は追記型履歴として残し、訂正・取消は従来どおり完了済みTodoの詳細画面で行う。
- Todo、ManagedItem、Consumableの名前から各詳細画面へ移動するリンクは維持する。
- ManagedItemにはクイック操作を追加しない。担当変更、Todo編集、Consumable編集、削除、ピン留め、一括操作も検索結果へ置かない。
- 在庫変更とTodo完了には、それぞれホームのピン留めで使う`QuickStockStatusControl`と、Todoカード等で使う`CompleteTodoPanel`を再利用する。検索専用の保存処理や汎用操作基盤は作らない。
- 操作後は`/search`を再検証する。在庫変更後は選択状態を最新にし、Todo完了後はpendingだけを返す検索結果から完了したTodoを消す。
- Todo完了後に関連する管理対象も更新するため、検索結果へ現在回の`managedItemId`を内部データとして追加する。`rule_snapshot`がある場合は現在回の値を使う。画面には表示せず、新しい保存項目やmigrationは追加しない。
- 完了ダイアログへ渡す現在利用者と実施者候補は、認証済み利用者と同じ家庭のメンバーから取得する。検索クエリーと操作の家庭単位の認可は既存経路を維持する。
- ボタンは名称、`aria-pressed`、既存のダイアログフォーカス制御、`:focus-visible`を維持する。長い名前や320px幅では操作を次の行へ送り、横スクロールを発生させない。

## YDR-042との関係

YDR-042のうち、画面内検索と横断検索の役割表にある「続きの操作は詳細画面へ移動する」と、検索結果から在庫状態を直接変更しないという初期境界を本決定で置き換える。

下部ナビゲーションの入口、URLクエリー、検索対象となる3種類の名前、種類別表示、補助情報、一致規則、種類ごと20件の上限、家庭単位の認可、ピン留めと横断検索の役割分担はYDR-042の決定を維持する。

## 結果

- 「検索 → 卵 → 少ない」のように、対象を見つけた場所で在庫を変更できる。
- 未完了Todoは検索結果から既存と同じ実施日・実施者の規則で完了でき、完了後は結果から消える。
- 詳細リンクは残るため、確認や今回対象外の編集が必要な場合は従来どおり詳細画面へ進める。
- 操作を2種類に固定し、横断検索が汎用編集画面へ広がることを防げる。

## 見直す条件

- 検索結果の操作が増え、名前・補助情報・詳細リンクを確認しづらくなった場合。
- 320px幅やキーボード操作で、3状態ボタンまたは完了ダイアログが使いにくいと確認された場合。
- 実利用で誤った在庫変更やTodo完了が増え、検索結果では確認手順を追加する必要が生じた場合。
- 別の操作について、頻繁に使い、短時間で終わり、既存画面でもクイック操作として提供されている具体的な需要が確認された場合。
