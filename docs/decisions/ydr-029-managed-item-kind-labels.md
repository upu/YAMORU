# YDR-029: 大分類の表示ラベルを登録時に選びやすい短い表現へ揃える

- 状態: Accepted
- 決定日: 2026-08-24
- 置き換える決定: [YDR-028](ydr-028-managed-item-kind-item-type-tags.md)(`asset` / `service` / `obligation` / `other`の初期の表示ラベルのみ。`kind`・`item_type`・タグの役割分離、プリセットの管理方法、互換列と段階移行の判断は変更しない)

## 背景

[YDR-028](ydr-028-managed-item-kind-item-type-tags.md)は大分類の初期ラベルを「モノ・設備」「サービス・契約」「継続的な義務」「その他」と定めた。これは各大分類が何を含むかを説明する名称であり、決定時点では分類の境界を伝えることを優先していた。

家庭向けの画面で見直したところ、登録の場面ではこの説明的な名称が働きにくいことが分かった。大分類は登録の最初に一つ選ぶ入力であり、利用者はその場で選択肢を読み比べる。「モノ・設備」「サービス・契約」のように中黒で二語を並べると、選択肢どうしの見分けよりも「自分の対象はどちらの語に当たるか」の判断が先に立つ。「継続的な義務」は、固定資産税のように実際は年に一度支払う対象に対して硬く、家庭内で使う言葉から遠い。

## 決定

- 大分類の表示ラベルを次のとおりとする。

  | code | ラベル |
  |---|---|
  | `asset` | モノ |
  | `service` | サービス |
  | `obligation` | 支払い・手続き |
  | `other` | その他 |

- 変更するのは表示ラベルだけとする。`asset` / `service` / `obligation` / `other`というcode、各大分類が受け持つ対象の範囲、`sort_order`による並び順、有効状態、`legacy_kind`、`item_type`との親子関係は変更しない。
- ラベルは`managed_item_kinds.label`を正本とし、アプリ側にラベル文字列を持たせない。表示は現在と同じくこの列を読む。
- 適用済みの`d1/migrations/0005_managed_item_classification.sql`は書き換えず、追加の連番migrationで`label`を更新する。既存のManagedItem、分類行、外部リンク、Todo、Occurrence、履歴は作り直さない。
- 「継続的な義務」のような語は、画面ラベルとしては使わないが、分類の意味を説明する文脈ではプロダクト文書に残してよい。画面ラベルと概念説明は別のものとして扱い、機械的に一括置換しない。

## 結果

- 登録時の大分類選択が「モノ」「サービス」「支払い・手続き」「その他」の四択になり、選択肢どうしを短い語で見分けられる。
- 固定資産税は「支払い・手続き」に属し、家庭内で使う言葉のまま台帳と詳細に表示される。
- codeを変更しないため、既存データ、`item_type`のプリセット、互換列`managed_items.kind`の読み替えはいずれも影響を受けない。
- 分類の意味そのものは変えていないため、[YDR-028](ydr-028-managed-item-kind-item-type-tags.md)の見直す条件はそのまま引き継ぐ。

## 見直す条件

- 「モノ」と「設備」を別の大分類として扱いたい事例が家庭内で繰り返し現れた場合。
- 「支払い・手続き」に、支払いを伴わない手続きと支払いそのものが混在して選びにくいという問題が確認された場合。
- ラベルの短さによって、どの大分類を選べばよいか判断できない対象が繰り返し現れた場合。
