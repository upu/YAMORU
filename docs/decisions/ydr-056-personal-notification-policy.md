# YDR-056: 個人の通知設定と配信判定を共有予定から分離する

## 操作と境界

[#441](https://github.com/upu/YAMORU/issues/441)は[YDR-050](ydr-050-conversation-reminders.md)を具体化する。アカウントの連携管理から本人の設定へ到達する。オン・オフ、通知先、まとめ時刻、静かな時間、重要度別の再通知と候補ごとのmute/snoozeは戻せる個人設定である。Todoの延期や家庭の期限は変更しない。

設定は利用者・家庭ごとに一つ、通知先は本人の有効な接続一つ。初期状態は無効、09:00の日次まとめ、Asia/Tokyo、22:00〜08:00の休止、再通知なし。候補ごとの休止は同じ候補区間でのみ有効。設定revisionで古い画面の上書きを拒否する。

配信履歴は受領、案内報告、結果不明、見送り理由を区別し、既読を持たない。候補の解消後も履歴を残す。配信の実行、lease、outbox、購読は#442が担当する。#441の配信判定は送信の確保ではなく、#442は確保後・送信直前にも再判定する。

## 保存と互換性

0035は新しいテーブルと一意索引だけを追加する。設定・候補休止・履歴にhousehold_idとuser_idを持たせ、通知先は接続の本人・家庭との複合FKで束縛する。履歴は対象が消えても候補IDを保持し、重複抑止用の最小記録は候補の存続中保持する。履歴詳細は90日で削除可能とする。

0036は候補にnullableなfirst_detected_atを追加し、既存行は保存済みgenerated_atで補う。旧WorkerのINSERTにはtriggerで補完し、内容の再生成では維持する。元の列、ID、生成時刻は書き換えない。

| 状態 | 読み書きと互換性 |
|---|---|
| 現Worker・現schema | 従来の予定・候補・OAuthが動く。通知設定はない |
| 0035・0036適用直後・現Worker | 従来の列、ID、時刻は不変。追加列はtriggerが補い、旧SQLの追加・更新・削除を維持 |
| 0035・0036適用後・新Worker | 本人設定と履歴を追加。旧Workerへ戻しても既存Webが動く |
| 互換期間終了後 | 旧構造を置換しないためcontract migrationは不要 |

家庭・利用者の削除は個人設定と履歴をcascadeで削除する。候補の削除は候補休止と最小重複抑止記録だけを削除し、履歴は残す。接続の解除は行を残し、毎回の有効性検査で配信を拒否する。接続行の物理削除ではその接続の設定・履歴をcascadeで削除する。更新時の競合や途中失敗は原子的に取り消す。適用済みmigrationは変更せず、問題時は追加migrationで修正する。

## 時刻と判定

保存値から毎回、最新の配信可否と次回時刻を計算する。送信済み候補はrevisionの変化だけで再送しない。結果不明は自動再送しない。静かな時間とsnoozeの延期は通知回数を消費しない。日次まとめの予定時刻が休止に重なった場合は休止明けへ移す。

初回配信の起点は、Todoは家庭の暦で候補になった日の開始、在庫は同じ候補区間の初回検出時刻とする。期限を迎えているTodoの初回走査や内容更新がまとめ時刻を過ぎても、既に迎えた配信時刻を翌日へ動かさない。在庫の過去の観測時刻は推測せず、#438で観測履歴が入るまでは検出できた時刻を使う。

時差とDSTはTemporal polyfillを使用する。欠けた現地時刻は遷移直後、重複した現地時刻は最初の時刻へ解決する。[Temporal公式仕様](https://tc39.es/proposal-temporal/docs/zoneddatetime.html)に従い、家庭の暦とは独立させる。

## 検証

初期値、DST、休止直前の設定変更、再通知の間隔と上限、他人・他家庭・解除済み接続の拒否、共有予定の不変、履歴と候補削除、更新DBと空DB、batch rollbackをテストする。実接続での到達確認は#442/#444で行う。
