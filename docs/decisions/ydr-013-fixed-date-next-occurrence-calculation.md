# YDR-013: 固定日基準の次回予定枠を元の予定と実際の解決日時から決める

- 状態: Accepted
- 決定日: 2026-08-12

## 背景

「解決日時より後の予定枠」とだけ定義すると、7月1日予定を6月28日に前倒し完了した場合に7月1日を再生成し、同じ予定回を二度扱う可能性がある。一方、アプリへの記録日時を使うと、バックデート完了で不要な予定枠まで飛ばしてしまう。

## 決定

- 最初の候補は、解決したOccurrenceの`scheduled_for`より後にある次の暦上の予定枠とする。
- 候補が実際の解決日時以前である間、さらに次の暦上の予定枠へ進める。
- 完了時の実際の解決日時は`occurred_at`、スキップ時は操作日時とする。
- `recorded_at`は次回予定枠の計算に使わない。

例:

- 7月1日予定を6月28日に完了: 次回は8月1日。
- 7月1日予定を8月10日に完了: 次回は9月1日。
- 8月10日の完了を10月5日に記録: 次回は9月1日で、生成直後から期限切れ。

## 結果

前倒し、遅延、バックデートのいずれでも、元の暦上の予定を壊さず単一未解決Todo方式を維持できる。

## 見直す条件

月末や祝日調整など、暦上の予定枠自体を変更する機能を追加する場合。
