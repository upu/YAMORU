# YDR-018: アカウント単位のニックネームを家庭内Member表示名と同一概念として扱う

- 状態: Accepted
- 決定日: 2026-08-13

## 背景

Issue #30で、家庭を作る前に利用者自身のニックネームを登録し、その値を家庭名の初期値(「<ニックネーム>の家庭」)へ使う機能が必要になった。ニックネームは家庭作成前(=`household_members`行が存在する前)に登録できる必要があるため、家庭の存在に依存しないアカウント単位の保存先が要る。

一方、`docs/product/yamoru-project-plan.md` §7の概念データモデルには`Member`(家族、表示名)という、家庭内の表示名を表す概念が既に記載されている。ただし`household_members`テーブルには表示名カラムがまだ実装されていない。Issue #30は「アカウント単位のニックネームと、将来の家庭内表示名を同一概念にするかは実装時に明示する。黙って二重管理しない」ことを求めている。

## 決定

- アカウント単位のニックネームを、将来のMember表示名と**同一概念**として扱う。両者を別々のテーブル・カラムで二重管理しない。
- 利用者に1対1で紐づく`profiles`テーブル(`user_id`主キー、`nickname`カラム)にニックネームを保存する。`household_id`を持たず、家庭作成前から参照・登録できる。
- MVPでは`household_members.user_id`がunique制約([#28](https://github.com/upu/YAMORU/issues/28)で追加)により一人一家庭に限定されているため、「アカウント単位の値」と「家庭内の表示名」は常に一致し、矛盾しない。
- 家庭作成フォームの初期値(「<ニックネーム>の家庭」)は作成時点で一度だけ生成し、`households.name`として独立したカラムに保存する。後からニックネームを変更しても、既存の家庭名を自動的に変更しない。

## 結果

- 家庭作成前でも、認証済み利用者ごとに一つのニックネームを登録・参照できる。
- 将来、家庭メンバー一覧などで表示名が必要になった場合も、新しいテーブルやカラムを追加せず`profiles.nickname`をそのまま使える。

## 見直す条件

- 複数家庭対応(一人が複数の家庭に所属できる機能)を導入する。その時点で「アカウント単位の値」と「家庭ごとの表示名」が一致するとは限らなくなるため、表示名の持ち方(家庭ごとに個別の値を持たせるか、既定値としてアカウント単位の値を使うか)を新しいYDRで再設計する。
