# YDR-057: 在庫の観測と補充を分け、訂正を追記する

[#438](https://github.com/upu/YAMORU/issues/438)で[YDR-049](ydr-049-conversation-command-boundary.md)の在庫契約を具体化する。[YDR-012](ydr-012-separate-occurred-recorded-scheduled-due.md)の実施・記録時刻の区別を維持する。

## 操作と事実

在庫の「ある・少ない・ない」は観測、補充は別の事実とする。観測で補充日を変えない。実施日または実際の時刻、実施者、記録者、接続元を保存する。数量・購入日・使用開始日を補完しない。家庭共有の事実であり、個人の通知設定やピン留めは変更しない。

原記録を更新・削除して訂正を表さず、直前の版へ結び付く訂正・取消を追記する。元の実施者が不明なら、訂正した人を実施者に置き換えない。actorは認証された本人、performerは実施者、clientは受付記録のbusiness keyから引く接続元とする。Webの明確な在庫ボタン・補充も同じ保存処理を使う。

## 現在状態への反映

日付だけの入力と実際の時刻を区別する。`observed_on/refilled_on`または`observed_at/refilled_at`を受け付け、`now`はprepare時刻へ固定する。Webの現在状態の操作はその時点を明示した観測として記録する。

現在の確定した状態より明らかに古い記録は履歴だけへ追加する。同日の異なる状態など順序を決められない場合は、日時、履歴だけを追加する意図、または現在の在庫を確認する。記録時刻だけで実施順を推定しない。

`application: history_only`は現在状態を変更しない操作の意図であり、確認や権限の代用ではない。`current_observation`は利用者が明示した現在の状態を追加する事実で、訂正等と同じbatchへまとめる。曖昧さを解くために必要な値を受け取るものであり、`confirmed: true`を認可根拠にしない。#437の確認・権限の共通処理を迂回しない。

現在状態の根拠となる記録を取消・日付訂正するときは、残る有効な記録から一意に決まる状態だけを反映する。決まらなければ現在の観測を求め、家族の後続確認を巻き戻さない。

根拠の再計算は有効な他記録100件までに制限し、それ以上は現在の観測を求める。保存済み状態はWeb履歴で日付不明と表示する。会話の実施履歴には観測・補充・訂正・取消だけを返し、保存状態の捕捉を利用者の実施事実として返さない。

## 保存と段階移行

0037は追加だけとする。既存`consumable_refills`を元の補充記録として保持し、ID・日付・記録時刻を変えない。版を持つ`consumable_stock_events`とその読み取り用投影、現在状態の根拠、競合検査を追加する。家庭一致は複合FK、同じ操作の再送はbusiness key、版の分岐は直前版の一意性で検証する。

既存補充の実施者・記録元は不明のまま取り込む。保存済み在庫と旧Workerの在庫変更は`state_snapshot`として扱い、観測日を作らない。その記録時刻は保存状態を取り込んだ時刻であり、家庭で在庫を観測した時刻ではない。元の`consumables.updated_at`も観測日へ流用しない。

| 状態 | 互換性 |
|---|---|
| 現Worker・現schema | 既存3状態の更新と補充記録が動く |
| 0037直後・現Worker | 旧列・ID・時刻は不変。旧SQLの追加・更新・削除を維持し、旧経路は不明なメタデータを補完しない |
| 0037後・新Worker | 事実・投影・競合検査・結果を同じbatchで保存する。旧Workerが読める現在状態も更新する。旧Workerへ戻す場合は外部commitと新しい訂正操作を止め、旧画面では補充の原記録を表示する。訂正の閲覧・再訂正は新Workerへ戻して再開する |
| 互換期間後 | 元の補充表は原記録として維持する。今回rename/drop/置換はなく、contract migrationを前提にしない |

家庭・消耗品の削除は事実・版・投影へcascadeする。実施者の家庭離脱では履歴を消さず、ユーザー削除で不明にする。途中失敗はD1 batch全体を取り消す。適用済みmigrationは変更せず、問題は追加migrationで修正する。

## 検証

空DBと更新DB、旧SQL、元のID・時刻の保持、観測で補充日不変、冪等性、版競合、過去日・同日・不明値、訂正と後続観測、家庭境界・実施者、FK/cascade、batch直前の競合とrollbackを実D1で検証する。Webの既存3状態・補充・履歴・訂正は画面テストで確認する。実dotとの接続は#439/#444で区別して確認する。
