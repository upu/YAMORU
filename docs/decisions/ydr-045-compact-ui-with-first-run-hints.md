# YDR-045: 通常UIを1系統のコンパクト表示に統一し、初心者向けの説明は初回ヒントとヘルプへ置く

- 状態: Accepted
- 決定日: 2026-09-09

## 背景

YAMORUは家庭で毎日何度も開くアプリであり、画面内の説明文が増えるほど1画面に入る情報が減る。ホーム、Todo追加、在庫操作など複数のIssueで個別に説明を削ってきたが([Issue #359](https://github.com/upu/YAMORU/issues/359)、[#293](https://github.com/upu/YAMORU/issues/293)、[#327](https://github.com/upu/YAMORU/issues/327))、削った説明をどこへ置くかという共通方針がなかった。

一方で、アイコンだけの操作は使い始めた利用者に意味が伝わらないことがある。「初心者向け」と「慣れた人向け」の2系統のUIを持つと、表示分岐・テスト・設定項目が増え、個人開発で維持できない([Issue #361](https://github.com/upu/YAMORU/issues/361))。

## 決定

### 1. 通常のUIは1系統のコンパクト表示だけを持つ

- 日常的に繰り返す操作は、アイコンまたは短いラベルで表す。同じ意味の説明文を常時併記しない。
- 見た目から語を外しても、`aria-label`または`.sr-only`のテキストでアクセシブルネームを必ず残し、切り替え操作は`aria-pressed`で状態を示す。
- 見た目のアイコンを小さくしても、タップ領域は44px以上を保つ。
- 「シンプル表示 / 説明付き表示」のような表示スタイル切替は追加しない。UI部品ごとに2種類の表示を維持しない。

### 2. 意味が伝わりにくい操作は、初回だけヒントで補う

- ヒントはその操作が現れた場所に短く出し、最初に画面全体のチュートリアルを見せない。
- 既読状態はブラウザローカル(`localStorage`の`yamoru.hint-seen.<hintId>`)に持つ。利用者設定やDBの項目は追加しない。
- 既読を記録できない環境では、ヒントを出さない。記録できないまま出すと同じヒントを毎回繰り返すため。
- ヒントは、閉じる操作をしたときと、その操作自体を実行したときに既読にする。
- 実装は`src/app/first-run-hint.tsx`の小さな共通部品だけとし、外部のチュートリアルライブラリや汎用オンボーディング基盤を導入しない。

### 3. 後から確認したい説明は`/help`へ集約する

- `/help`は問い合わせ用のバージョン情報に加えて、YAMORUで扱うもの(Todo、台帳、消耗品)、主なアイコンの意味、日常的な操作を置く。
- 同じ説明を通常画面とヘルプへ重複して書かない。画面側から外した説明の置き場所はヘルプとする。

### 4. 適用は必要な操作から少しずつ広げる

- 全画面を一括でアイコン化しない。実利用で説明不足や邪魔さを確認しながら、操作単位で適用する。
- 「操作ヒントを表示する」個人設定は、実利用で常時表示の必要性が確認できた場合に別Issueで検討する。

## 検討した案

- **案1(採用)**: UIを1系統のコンパクト表示に統一し、初回ヒントとヘルプで補う。維持する表示は1種類だけで済み、説明の置き場所が1か所に定まる。
- 案2: 個人設定で「シンプル表示 / 説明付き表示」を切り替える。慣れていない利用者に常時説明を出せるが、部品ごとに2種類の表示・テスト・設定を維持する必要があり、個人開発の負担に見合わない。
- 案3: 従来どおりアイコンと説明文を常時併記する。追加実装は不要だが、毎日使う画面の情報密度が下がり続ける。
- 案4: 初回に画面全体のチュートリアルを表示する。一度に説明できるが、使い始めを妨げ、専用の基盤とその保守が必要になる。

## 結果

- 日常操作の画面は説明文が減り、1画面で扱える件数が増える。
- アイコンだけの表示でも、支援技術からは操作名と状態を判別できる。
- 初めての利用者には、その操作の場所で一度だけ短い説明が出る。二度目以降は出ない。
- ブラウザのデータを消す、別の端末やブラウザを使う、プライベートウィンドウを使う場合、ヒントの既読状態は引き継がれない。クロスデバイス同期は行わない。

## 見直す条件

- 実利用で、一度きりのヒントでは操作の意味が伝わらないと分かった場合。「操作ヒントを表示する」単一設定の追加を別Issueで検討する(画面全体の表示スタイル設定にはしない)。
- ヒントを出す操作が増え、置き場所や表示の重なりを個別に判断できなくなった場合。表示位置と同時表示件数の規則を追加する。
- 既読状態のクロスデバイス同期が実利用で必要になった場合。DBへ持つ方式を新しいYDRで検討する。
