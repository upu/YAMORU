# YDR-031: 予定日未定Todoをホームの要対応表示から外し、Todo一覧で扱う

- 状態: Accepted
- 決定日: 2026-08-25
- 置き換える決定: [YDR-030](ydr-030-undated-one-time-task-occurrences.md)(「日付未定Todoはホームの独立した『予定日未定』区分へ表示する」という表示先の決定のみ。`scheduled_for`/`due_at`のNULLペア、一回限りTodoへの限定、具体日と未定の往復、日付未定中は延期を提供しないこと、未定のまま完了できること、一意制約の扱いは変更しない)

## 背景

[YDR-030](ydr-030-undated-one-time-task-occurrences.md)は、実施する必要は確定していても時期が決まっていない一回限りTodoを、仮の日付を入れずに扱えるようにし、ホームの独立した「予定日未定」区分へ表示すると定めた。

実利用では、外部機関からの通知待ちなど数か月間着手できない項目がホームの分かりやすい位置と「件の予定」に残り続け、いま対応すべき内容を把握しにくくなることが分かった([Issue #202](https://github.com/upu/YAMORU/issues/202))。ホームを「いま対応すること」に絞る整理は、7日より先の予定と完了日基準Todoの推奨期間前について既に行っている。

一方、ホームから外すだけでは、特にManagedItemに紐づかないTodoを再発見する経路がなくなる。[Issue #201](https://github.com/upu/YAMORU/issues/201)で未完了Todoをすべて確認できるTodo一覧を用意し、[Issue #203](https://github.com/upu/YAMORU/issues/203)でTodo詳細・編集を用意したため、再発見と予定日設定の場が揃った。

## 決定

- 予定日未定Todoを、ホームのどの区分にも表示しない。「予定日未定」区分自体を置かない。
- ホーム上部の「件の予定」に予定日未定Todoを数えない。「件が期限切れ」の数え方も変更しない。
- 予定日未定Todoは、すべてのTodo一覧(`/todos`)へ日付があるTodoの後ろに表示し、そこから予定日を設定できるようにする。Todo詳細の編集からも設定できる。
- 予定日を設定したTodoは、日付に応じてホームの期限切れ・今日・近日へ再び表示する。この分類規則は変更しない。
- ホームに表示できるTodoも完了記録もない場合の空表示は、「Todoがない」と言い切らず、すべてのTodoへの導線を示す。
- 予定日未定であること自体は状態として持たない。`scheduled_for`と`due_at`がNULLであることがそのまま「予定日未定」であり、`waiting`のような新しいTodo状態は追加しない(YDR-030の見直し条件のまま)。

## YDR-030との関係

この決定はYDR-030を全面的には置き換えない。日付未定を`status = 'pending'`のOccurrenceとして持つこと、NULLペアを`recurrence_basis = 'once'`に限ること、具体日と未定を往復できること、日付未定中は延期を提供しないこと、未定のまま完了でき次のOccurrenceを作らないこと、二種類の一意制約の扱いは、いずれもそのまま維持する。本決定が置き換えるのは「ホームの独立した『予定日未定』区分へ表示する」という表示先の決定だけである。

## 結果

- ホームは、いま対応できるTodo(期限切れ・今日・そろそろ・近日)と最近の実施だけを示す。
- 着手できない項目が「件の予定」に積み上がらず、対応状況の数字が実際に動かせる件数と一致する。
- 予定日未定Todoの確認と予定日設定は、すべてのTodo一覧とTodo詳細に集約される。ホームからTodo一覧への導線は、モバイルでも隠さない。
- ホームだけを見る利用者からは、予定日未定Todoが見えなくなる。再発見はTodo一覧の役割に依存する。

## 見直す条件

- Todo一覧を開く習慣がつかず、予定日未定Todoが長期間放置される事例が家庭内で確認された場合。
- 予定日未定Todoに、期限とは別の再確認時期(リマインド日など)を持たせる必要が確認された場合。
- 予定日以外の待機理由を状態として区別する必要が確認された場合(YDR-030の見直し条件と同じ)。
