# YDR-028: ManagedItemの大分類、詳しい種類、タグの役割を分離する

- 状態: Superseded by [YDR-029](ydr-029-managed-item-kind-labels.md)(初期の表示ラベル(`asset`=モノ・設備、`service`=サービス・契約、`obligation`=継続的な義務)のみ置き換え。`kind`・`item_type`・タグの役割分離、プリセットの管理方法、互換列と段階移行の判断は[YDR-029](ydr-029-managed-item-kind-labels.md)でも維持される)
- 決定日: 2026-08-24
- 関連する決定: [YDR-002](ydr-002-minimal-managed-item.md)

## 背景

YDR-002では、家電などの物理的な対象と契約・税金などを`ManagedItem`に統合し、最小限の`kind`で区別すると決めた。家庭内で実際に登録する対象が増えると、従来の「家電」「住宅設備」「ペット用品」「契約」「その他」という一段の分類では、管理上の性質と具体的な対象種別が混在する。

一方、利用者が提案したタグは「ペット」「住まい」「子ども」のような複数の文脈を重ねる用途に向く。これを管理上の性質と同じ概念にすると、分類ごとに変わる入力や将来の機能を安定して判断できない。

## 決定

- `kind`は、管理上の性質とライフサイクルを表す単一の大分類とする。初期値は`asset`(モノ・設備)、`service`(サービス・契約)、`obligation`(継続的な義務)、`other`(その他)とする。([YDR-029](ydr-029-managed-item-kind-labels.md)で表示ラベルのみを「モノ」「サービス」「支払い・手続き」「その他」へ置き換えた。codeと分類の意味は変更していない)
- `item_type`は、`kind`の配下で対象を具体化する一つの種類とする。プリセットからの選択を基本とし、該当する候補がなければ自由入力でき、未指定も許容する。
- プリセットは無効化可能なマスタとして管理する。登録・編集時は有効な大分類と、その大分類に属する有効な詳しい種類だけを受け付ける。
- 既存の`managed_items.kind`は移行期間の互換列として保持し、新しい分類を別テーブルへ保存する。既存行はデータ、外部リンク、Todo、Occurrence、履歴を作り直さず分類を補完する。
- タグは、将来「ペット」「住まい」「税金」「子ども」のような横断的な文脈を一つのManagedItemへ複数付与する概念とする。`kind`や`item_type`の代用にはしない。
- タグの保存形式、登録・管理・検索UIはIssue #41の対象外とし、実需要を確認して別Issueで設計する。

### 切り替えとロールバック

- 連番migrationを先に適用し、既存の`managed_items.kind`から新しい分類行を補完してから、新しいアプリへ切り替える。preview / productionへの手動適用はこのIssueでは行わない。
- 新しいアプリは新旧両方の列を同じ処理で書き込む。旧アプリは従来どおり`managed_items.kind`だけを読み書きできるため、新しいアプリから旧アプリへ戻しても既存画面は動作する。
- 新しいアプリは、分類行がまだないManagedItemを旧`kind`から読み替える。また、旧アプリが`kind`を別の値へ変更したことを検出した場合は、古い分類行より旧`kind`を優先する。名前だけが編集され`kind`が一致している場合は、新しい分類を維持する。
- 旧列と互換処理の削除は、新しいアプリへの切り替えとロールバック期間が完了した後の別Issueとする。適用済みmigrationは書き換えない。

## 結果

- 猫用給水機は`asset` / `pet_water_fountain`、習い事は`service` / `lesson`、固定資産税は`obligation` / `property_tax`のように一貫して表現できる。
- 一つの対象が複数の大分類へ同時に属する曖昧さを避け、分類に応じた将来の入力や表示を追加しやすくなる。
- 横断検索に適した複数ラベルはタグとして後から追加でき、現在の分類モデルを作り直す必要がない。
- YDR-002の最小限のManagedItemと、Asset・ObligationをManagedItemへ統合する判断は変更しない。

## 見直す条件

- 一つのManagedItemが同時に複数の管理ライフサイクルを持ち、単一の`kind`では実運用を表現できない事例が確認された場合。
- タグによる横断検索・絞り込みが家庭内の日常利用で繰り返し必要になった場合。
- プリセットと自由入力の併用により、同じ種類が表記揺れで多数重複する問題が確認された場合。
